# 1. Высокопроизводительный брокер сообщений

Например, собственный аналог сильно упрощённого Kafka/NATS.

### Идея

Разработать брокер:

```text
Producer
   │
   ▼
┌───────────────┐
│ Message Broker│
│               │
│ ┌───────────┐ │
│ │ Partition │ │
│ │ Partition │ │
│ │ Partition │ │
│ └───────────┘ │
└───────┬───────┘
        │
        ▼
     Consumer
```

C++/Rust.

### Исследовательская часть

Вот здесь уже появляется настоящая магистратура:

> Исследование методов повышения пропускной способности брокеров сообщений за счёт оптимизации конкурентного доступа к памяти и сетевого I/O.

Можно сравнить:

- mutex;
    
- spinlock;
    
- lock-free структуры;
    
- SPSC/MPSC/MPMC queues;
    
- batching;
    
- zero-copy;
    
- memory-mapped files;
    
- io_uring;
    
- epoll;
    
- TCP vs UDP/QUIC;
    
- разные модели thread-per-core;
    
- NUMA-aware allocation.
    

### Что измерять

```text
throughput
latency p50
latency p95
latency p99
CPU utilization
memory consumption
messages/sec
MB/sec
```

И сравнить:

```text
Kafka
NATS
RabbitMQ
твой implementation
```

Не обязательно пытаться победить Kafka вообще. Можно сформулировать **узкую область**, например:

> Брокер для low-latency взаимодействия микросервисов внутри одного датацентра.

### Потенциал

Очень хороший.

Можно постепенно получить:

```text
broker
 ↓
client SDK
 ↓
monitoring
 ↓
cluster
 ↓
replication
 ↓
web UI
```

И это уже вполне серьёзный open-source проект.

# 2. Распределённое объектное хранилище

Упрощённый:

```text
        Client
           │
           ▼
       ┌───────┐
       │  API  │
       └───┬───┘
           │
     ┌─────┼─────┐
     ▼     ▼     ▼
```

> Исследование алгоритмов распределения объектов и репликации данных в распределённом объектном хранилище.

- consistent hashing;
    
- rendezvous hashing;
    
- replication factor;
    
- erasure coding;
    
- data placement;
    
- rebalancing;
    
- quorum;
    
- consistency levels;
    
- failure recovery.
    

### Очень интересный эксперимент

Например:

```text
Replication:
RF=2
RF=3
RF=5

vs

Erasure Coding:
4+2
8+4
```

И смотреть:

```text
storage overhead
write throughput
read throughput
recovery time
network traffic
```

Это уже выглядит **очень магистерски**.

### А продуктовая часть

Получается:

```bash
mycloud put file.bin
mycloud get file.bin
```

плюс:

```text
S3-compatible API
Web UI
CLI
Docker deployment
cluster management
monitoring
```

Потенциально это уже реальный инфраструктурный продукт.

# 4. WASM runtime для backend

Это уже **очень серьёзный системный проект**.

Идея:

```text
             Backend
                │
       ┌────────┴────────┐
       │                 │
   Rust/C++          WASM modules
       │                 │
       └───────┬─────────┘
               ▼
        WASM Runtime
               │
       ┌───────┼───────┐
       ▼       ▼       ▼
     Module  Module  Module
```

Например, пользователь может загружать собственную бизнес-логику:

```rust
fn process(request) -> response
```

а сервер безопасно выполняет её в sandbox.

### Исследование

Сравнить:

```text
native process
Docker container
WASM interpreter
WASM JIT
WASM AOT
```

по:

- startup latency;
    
- execution latency;
    
- memory;
    
- throughput;
    
- isolation;
    
- overhead.
    

Очень сильная тема:

> Исследование методов изоляции и ускорения выполнения пользовательского кода в серверных системах на основе WebAssembly.

### Продуктовый потенциал

Можно сделать:

**Serverless-платформу для WASM.**

Например:

```text
deploy function.wasm

POST /functions/my-function
```

А дальше:

```text
scheduler
runtime
autoscaling
sandbox
metrics
billing
```

Это уже потенциально SaaS.

# 6. Собственный backend runtime

Это вариант для человека, которому хочется **максимально прокачать C++/Rust**.

Не framework типа:

```cpp
app.get("/users", handler);
```

а исследование самой архитектуры.

Например:

> Исследование моделей конкурентного выполнения HTTP-сервисов на многоядерных системах.

Сделать runtime:

```text
                HTTP
                 │
                 ▼
          ┌─────────────┐
          │ Load Balancer│
          └──────┬──────┘
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
    Core 0     Core 1    Core 2
       │         │         │
    EventLoop EventLoop EventLoop
```

Исследовать:

```text
thread pool
event loop
proactor
reactor
thread-per-core
work stealing
```

И сравнить с:

```text
nginx
envoy
tokio
asio
```

Особенно интересно сделать реализацию через:

- `io_uring`;
    
- lock-free queues;
    
- custom allocator;
    
- coroutines;
    
- NUMA-aware scheduling.
